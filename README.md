# Bcome

An automated career advisor for Australian students in Years 10–12. Students answer an adaptive RIASEC (Holland) questionnaire, get matched to occupations using Jobs and Skills Australia employment projections, and receive a plan covering the rest of school, study or training, and their first years at work.

## How it works

1. **Adaptive questionnaire** (`src/lib/questionnaire/`, questions in `data/questions/riasec-au.json`). Everyone answers 18 interest items (3 per RIASEC type), 10 work-value items, subjects and plans. Deeper interest items are asked only for the types whose ranking is still unclear, so a clear-cut student answers about 35 questions and a mixed profile up to 65.
2. **Matching** (`src/lib/careers/matching.ts`). Rule-based and explainable. Each occupation gets a fit score from interests (50%), values (15%), subjects (10%), preferred pathway (10%) and job outlook (15%), plus the reasons and cautions behind it (e.g. "Courses often require Chemistry").
3. **Outlook** (`src/lib/careers/outlook.ts`). 5- and 10-year growth from JSA projections to May 2035. Where an occupation's own figure isn't loaded, it is estimated from its ANZSCO major group adjusted for industry growth, labelled as an estimate and never rated above "good". The 15-year view is an indicative scenario: the 10-year band moved up for long-run demand drivers (ageing population, net zero, digital, housing…) and down for high exposure to AI and automation.
4. **Plan** (`src/lib/plan/`). With `ANTHROPIC_API_KEY` set, Claude writes the plan from the matched data only. The response is validated (shape, and it may only name careers we supplied); otherwise, or with no key, a deterministic template writes it. Students always get a plan.

## Getting started

Requires Node 22.18 or later.

```bash
npm install
cp .env.example .env.local   # fill in Supabase and (optionally) Anthropic keys
npm run dev                  # http://localhost:3000
```

The questionnaire and plans work without Supabase. Accounts and saving switch on once the Supabase variables are set.

### Supabase

1. Create a project in the **Sydney (ap-southeast-2)** region.
2. Run `supabase/migrations/20261021000000_init.sql`, then `supabase/seed.sql` (SQL editor or `supabase db push`).
3. In Auth settings, enable email sign-in and add `<your-site>/auth/callback` as a redirect URL.

Row Level Security: students see their own data; careers advisers see students at their school; parents see their child's plans only after a link (created by the server when a student invites them) and their consent. Advisers can mark a plan reviewed but can't edit it. `supabase/tests/rls-checks.sql` exercises these rules on plain Postgres.

## Commands

| Command | What it does |
| --- | --- |
| `npm test` | Unit tests (questionnaire, matching, outlook, plan validation, import parser) |
| `npm run test:profiles` | Runs six imaginary students through the whole pipeline and writes their plans to `test-output/` |
| `npm run data:validate` | Checks the JSON in `data/` after edits |
| `npm run data:import-jsa -- <file.xlsx>` | Loads occupation-level JSA projections (see below) |
| `npm run db:seed-sql` | Rebuilds `supabase/seed.sql` from `data/` |

## Loading the full JSA projections

`data/outlook/jsa-2025.json` holds the published summary figures (major groups, industries, skill levels and seven named occupations). To use projections for every occupation:

1. Download *Employment Projections – May 2025 to May 2035.xlsx* from <https://www.jobsandskills.gov.au/data/employment-projections> into `data/raw/`.
2. `npm run data:import-jsa -- data/raw/<file>.xlsx --dry-run` to check the columns it found, then run it without `--dry-run`.
3. `npm run db:seed-sql` and re-run the seed.

If JSA changes the layout, pass `--sheet`, `--code-col`, `--g5-col` and `--g10-col`.

## Editing content

Careers advisers can edit without touching code:

- **Questions:** `data/questions/riasec-au.json`. Tier 1 items are always asked; tier 2 and 3 only when needed. Conditional questions use `showIf`.
- **Occupations:** `data/occupations/occupations.json`. Holland code, values, helpful and often-required subjects, skills, pathways, AI exposure and demand drivers. These are editorial judgements and should be reviewed by a careers professional.

Run `npm run data:validate` after any edit.

## Sample output

`docs/sample-plans/` has plans for the six test students, generated by the template writer. They're the quickest way to review matching quality.

## Known limitations

- Only the 7 occupations JSA names in its summary have occupation-level projections until the full file is imported; the rest use labelled estimates.
- Occupation codes are ANZSCO 2022 unit groups. Check the ABS OSCA concordance when JSA moves to OSCA.
- Subject names are generic; NSW, VIC and QLD course names differ. State-specific subject lists are a good next step.
- The Next.js app has not yet been built against installed packages in CI; run `npm run build` after `npm install` and fix anything it flags.
